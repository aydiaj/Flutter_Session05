Loose data

Data + behavior

Familiar mental model

STEP 03 · FIELDS, METHODS AND THISGUIDED LAB

Fields hold state. Methods change it.

The BankAccount example from Chapter 6 shows why methods should apply business rules rather than leaving every field unrestricted.

State is not behavior.

Fields store what the object knows; methods define what it does.
Instance methods operate on the fields of the object they are called on. Methods called on the same object can read or modify its shared state, while different objects maintain their own instance state.

FIELD

Stored state

double balance = 0; belongs to each BankAccount instance.

METHOD

Behavior with rules

withdraw(amount) checks the balance before subtracting.

02 · State and behavior in BankAccount

Trace deposit and withdraw; see how methods operate on the same object.

main.dart · Fields Methods
class BankAccount {
  double balance = 0;

  void deposit(double amount) {
    if (amount > 0) balance += amount;
  }

  void withdraw(double amount) {
    if (amount > 0 && amount <= balance) {
      balance -= amount;
    } else {
      print('Withdrawal rejected.');
    }
  }

  void displayBalance() => print('Balance: ${balance.toStringAsFixed(2)}');
}

void main() {
  final account = BankAccount();
  account.deposit(100);
  account.withdraw(35);
  account.displayBalance();
  // TODO: Try withdrawing 100 and explain the result.
}

STEP 04 · CONSTRUCTOR FOUNDATIONSGUIDED LAB

Constructors: unnamed, shorthand and named

Chapter 6 introduces default and parameterized constructors, initializing-formal shorthand, named constructors and initializer lists.

DEFAULT

No explicit constructor

A class without a declared constructor receives an unnamed zero-argument constructor.

INITIALIZING FORMALS

Car(this.brand, ...)

Dart assigns constructor parameters directly into instance fields before the body runs.

NAMED

Point.origin()

Named constructors provide alternative, descriptive creation routes, without C#-style constructor overloads.

Read the constructor from left to right.

In Dart, this names the current instance when clarification is needed.
Car(this.brand, this.model, this.year) is shortened initialization, not a call to three methods. Point.origin() : x = 0, y = 0 initializes two fields using an initializer list.

STEP 05 · INITIALIZATION AND NULL SAFETYGUIDED LAB

Initialize safely before using the object

Carry forward what students learned about nullable types and final/const: those rules also govern Dart class fields.

Null safety applies to fields, too.

A non-nullable instance field must be initialized through a valid path before object construction finishes; this.x and initializer lists are common. Use String? when null is genuinely allowed; late postpones initialization and requires care.

NON-NULLABLE

final String name

Must be initialized once. A constructor can compute and assign it in its initializer list.

NULLABLE

String? researchTopic

May hold null. The ?? operator supplies a useful fallback.

CONST OBJECT

const CourseTag(...)

Final immutable fields and a const constructor allow compile-time constant instances.

STEP 06 · ENCAPSULATION AND PRIVACYGUIDED LAB

Protect state using getters and setters

Chapter 6 uses a Book/Student model to demonstrate private fields, controlled access and setter validation.

Important C# difference: the boundary is a library.

In Dart, _price is not class-private; it is library-private. Another class in the same library can access it, while a different importing library cannot. Getters and setters offer a deliberate public API. Do not promise that an underscore hides data from code in the same file.

C#

Access modifiers

private, public, and properties define member access.

DART

Underscore privacy

_price is library-private; get price and set price expose managed access.

STEP 09 · ABSTRACT CLASSESGUIDED LAB

Specify what every subclass must provide

Chapter 7 introduces GameCharacter, Warrior and Archer: shared methods alongside required attack() implementations.

Abstract does not mean empty.

An abstract class may provide shared implemented methods and also declare abstract methods without bodies. Every concrete subclass must implement the required ones. You cannot construct the abstract type directly.

ABSTRACT METHOD

void attack();

A concrete derived class must supply the behavior.

CONCRETE METHOD

showHealth()

Already implemented in the abstract parent and reused by subclasses.

STEP 10 · INTERFACES AND IMPLEMENTSGUIDED LAB

Agree to a contract without inheriting code

Chapter 7 compares extends and implements through Animal, Dog and Cat. This is especially useful for understanding interfaces in Flutter and Dart APIs.

EXTENDS

Inheritance

Get superclass implementation and optionally override it.

IMPLEMENTS

Contract

Supply all required public members yourself; no implementation is inherited.

C# COMPARISON

Implicit interfaces

Every Dart class defines an implicit interface; explicit interface class modifiers are an additional modern language feature.

An interface in Dart can begin as an ordinary class.

abstract class Person {

  void processPayment(double amount);

  void processPayment(double amount) => logActivity('$name paid \$$amount');

  void processPayment(double amount) => logActivity('$name received \$$amount');
}

  final people = <Person>[Student('Laila', 1001), Staff('Ali', 2002)];

  final payables = <Payable>[Student('Laila', 1001), Staff('Ali', 2002)];
